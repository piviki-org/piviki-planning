- (event) Create intent confirmed. Opening input: ILS for a Vietnamese community library in Tampere; MVP = librarian catalogue + circulation, and a patron website to browse and loan books.
- (event) Landscape research captured in addendum: hosted tools (TinyCat $3/mo, Libib $99/yr) undercut building; Vietnamese patron UI unverified in any; Vietnamese metadata thin so manual cataloguing dominates; GDPR applies to the association. Build-vs-adopt to be raised with user.
- (decision) Context: library not yet open (pre-launch). Collection ~300 books already acquired. Project scope = catalogue and circulate this collection.
- (decision) Reason to build #1: a fully customisable patron website in Vietnamese; existing tools lack a Vietnamese patron UI.
- (decision) Reason to build #2: kirjasto is a cornerstone project that may grow into a hub for the Vietnamese community in Tampere, later Finland. The library is the first piece.
- (assumption) User expects the collection to grow but not past free tiers of existing tools. Scale is NOT a reason to build; recorded honestly.
- (decision) Data ownership is a welcome side benefit, not a driver.
- (decision) Team: user (software/DevOps engineer, development) and wife (business master's student, product and operations). Explicit goal: a portfolio project built with AI for both.
- (decision) Mission: keep up reading habits and the Vietnamese language. Side goal: connect and support the Vietnamese community in Tampere and strengthen its bonds. More community activities will come later.
- (decision) Framing: keep kirjasto as an ILS, not a community hub, because it may scale up and out to other communities. Coach's hub reframing rejected; hub stays a parked vision.
- (decision) Donations: patrons donate books, which are catalogued and lent to others. Part of the library's operating model.
- (decision) Parked post-MVP: a perk system where donations earn points (e.g. higher loan limit, more renewals). The MVP stays focused on the core library system.
- (decision) Scale-out: keep both doors open, multi-library (other communities run their own library) and more languages. More languages is a late stage; multi-library is not built in the MVP but must not be designed out.
- (decision) i18n from day one: UI supports English and Vietnamese at MVP. More languages later on the same i18n foundation.
- (decision) Donor record: the MVP is designed so donations can later be tied to donors for perks, but donor tracking/perks are not implemented in the MVP. User asked for donor record + GDPR elaboration.
- (decision) Donor design note accepted: donations stored as their own record (copy, optional donor, date, consent); donor link removable without deleting the book; MVP records 'donated + date' with the donor optional; privacy notice names future perks to avoid a new purpose later. Details in addendum.
- (assumption) GDPR special category risk: patron list of a Vietnamese community library may arguably reveal ethnic origin. To verify against tietosuoja.fi before launch. Not legal advice.
- (decision) Working mode: coaching path. Walking remaining open questions together.
- (decision) Primary patrons, stage 1: parents with young children. Initial collection comes from a private collection; donated books will shape later patron groups.
- (decision) Collection focus: appropriate for school-age children. Grants are expected to help expand the collection.
- (decision) Accounts are adult-only. Minors do not get accounts; a parent borrows on the child's behalf. Sign-up has a self-declaration tick that the user is not a minor (18+). Coach reframed the user's 'gray area' as an explicit adult-only rule.
- (decision) Target audience is tech-capable at this stage; no accommodation for non-web users in the MVP.
- (decision) No physical location yet. The patron website is the main point of access to the library.
- (decision) Physical circulation: pickup and drop-off at the user's home for now. Flow: patron reserves online -> librarian marks 'ready for pickup' -> patron collects -> patron returns.
- (decision) Pickup/drop-off windows are announced weekly in a group chat (outside the system). Typically weekday evenings 17:00-21:00; weekends depend on personal plans.
- (decision) Parked: a borrowed shelf in a partner space. Needs separate discussion and planning.
- (decision) Rejected: postal delivery. Not worth it.
- (decision) Circulation flow confirmed: reserve -> ready for pickup -> picked up (loan starts) -> returned. Group chat does scheduling; the system tracks who has what.
- (decision) Notifications: the system emails patrons (e.g. ready for pickup). User asked about Gmail/Proton API; coach recommends a transactional email service, final choice for architecture.
- (decision) No-shows: reservation expires 7 days after 'ready for pickup'. Initially the librarian contacts the patron via WhatsApp/Zalo before expiring it.
- (decision) Loan rules (loan period, max items per patron, renewals and renewal limit, online self-renewal) are OPEN placeholders, to be decided with other stakeholders.
- (decision) Due-date reminders by email 5, 3 and 1 days before the due date. No fines, but overdue behaviour must affect future borrowing, as a consequence that builds responsibility. Exact consequence TBD.
- (decision) Queues: patrons can reserve a book that is on loan and join a queue. A book with a queue cannot be renewed by its current holder.
- (decision) Privacy: the librarian's home address is never shown on the public website; it is shared only with patrons who have a confirmed pickup.
- (decision) Reservation expiry is manual in the MVP: the system flags reservations 7 days after 'ready for pickup'; the librarian contacts the patron via WhatsApp/Zalo, then expires it.
- (decision) Patron phone number is stored, but not collected at registration: the librarian adds it at the patron's first pickup. Must be covered by the privacy notice (patron informed when it is collected).
- (decision) Overdue reminders: one email per week after the due date until the book is returned.
- (decision) Overdue consequence in the MVP: block while overdue (no new reservations until the overdue book is returned). Stronger consequences (probation, strikes) join the stakeholder placeholder list.
